THE KNOWLEDGE GAP

The code survives.
The reasoning often doesn't.

Important engineering context lives across commit messages, closed pull requests, incidents, design notes and the people who remember why a decision was made.

⌘

History is fragmented

A commit explains a change, but the motivating discussion may be buried in an issue or an old pull request.

⌕

Search finds mentions, not intent

Keyword search returns documents about a topic. It does not necessarily find the decision that governs it.

◷

Old decisions can mislead

A decision may have changed later. Historical context must be read with dates, references and supersession evidence.

HOW WHYTRACE WORKS

From repository history
to an evidence path.

WhyTrace turns repository artifacts into connected records, retrieves relevant relationships, and presents the source trail beside its explanation.

01 / INGEST

Connect a repository

Fetch bounded public GitHub metadata, commits, pull requests, issues and changed files.

02 / CONNECT

Build the graph

Represent artifacts as nodes and only create links supported by fetched repository records.

03 / INVESTIGATE

Traverse evidence

Retrieve records by relevance and inspect connected artifacts rather than relying on isolated text.

04 / EXPLAIN

Show what supports it

Present available rationale, source records, confidence limits and missing evidence honestly.

GitHub Token

Public repositories work without a token, subject to unauthenticated rate limits. A token increases the limit significantly.
